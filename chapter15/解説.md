# どうしてintではなくchar?

`char counter=0;`を用いており`int counter=0;`ではない理由は?

推測:「1バイトの変数なら安全だろう」という誤解を崩すためです。

`counter++`自体がatomicではない．読む → 足す → 書く操作がatomicではないため。


`std::atomic<char> counter{0}`とすると良い。atomicはcudaとかでよく出てくる。

# おまけ

C++の`std::atomic<double>()`は読み書き操作がのアトミック性が担保されるまでプログラマがCAS操作を行い対応していた。


[prometheus-cpp](https://github.com/jupp0r/prometheus-cpp)
のインクリメント

`void Gauge::Increment(const double value) { Change(value); }` 内部のコード。

```C++
void Gauge::Change(const double value) {
#if __cpp_lib_atomic_float >= 201711L
  value_.fetch_add(value);
#else
  // Pre-C++ 20 fallback: busy loop (which might be more expansive than using
  // fetch_add).
  auto current = value_.load();
  while (!value_.compare_exchange_weak(current, current + value)) {
    // intentionally empty block
    // 他のスレッドがvalueを書き換えた場合 value_をcurrentに上書きする
  }
#endif
}
```

C++11で`std::atomic::fetch_add()`は読み取り書き込みまでをアトミックにしている。
https://cpprefjp.github.io/reference/atomic/atomic/fetch_add.html


`std::atomic::compare_exchange_weak`が導入された。
https://cpprefjp.github.io/reference/atomic/atomic/compare_exchange_weak.html


C++20から`fetch_add()`の`float`/`double`が対応された。
上のprometheusコードではC++20より前のバージョンでは`atomic<double>`に`fetch_add()`が存在しないため、CAS(compare-and-swap)ループを用いることで加算している。



`value_.compare_exchange_weak(current, current + value)`で`value_`値が`current`値と同じ場合`current+value`に置き換えられる。そうでない場合`value_`値は`current`に上書きされる。


<details>
<summary> なぜdouble型のstd::atomic::fetch_add()の導入が遅れたのか? </summary>

> GPU や HPC の分野（Kokkos など）で「スレッドから double の合計に加算したい」という需要が強く、そこから提案 P0020 が出されました（2015年ごろ）。2017年11月の会議で C++20 に採択されています。__cpp_lib_atomic_float の値 201711L はこの採択時期を表しています。

> まとめると、ハードウェアに対応する命令がなく、作っても中身は CAS ループと同じで、仕様を決めるのも面倒だったため後回しにされた、ということです。そのため prometheus-cpp は C++20 より前では CAS ループを自前で書いていますし、C++20 で fetch_add を使っても、x86 では生成されるコードはほぼ同じです。

</details>
