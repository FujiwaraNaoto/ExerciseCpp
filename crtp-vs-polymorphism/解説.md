# CRTP vs 動的多態 (virtual) のパフォーマンス比較

bench.cpp

`Circle` / `Rect` の `area()` を100万個分合計する処理を、CRTP と virtual で書いて時間を比べる。

- 50回計測した中央値を表示
- 集計関数は `__attribute__((noinline))` にして、呼び出し元から型が分かって脱仮想化されるのを防いでいる
- 引数で要素数と計測回数を変えられる (`./p 要素数 回数`)

## 実行結果

```sh
$ g++ bench.cpp -o p -std=c++17 -O2 -Wall -Wextra
$ ./p
N = 1000000, reps = 50 (median)

[1] 単一型 (Circle のみ)
  0.968 ms  (x1.000)  CRTP           vector<CCircle>
  2.506 ms  (x2.588)  virtual        Shape* -> 連続配置
  2.742 ms  (x2.832)  virtual        vector<unique_ptr<Shape>>

[2] 混在 (Circle / Rect がランダム順)
  1.108 ms  (x1.000)  CRTP           型ごとの vector x2
  6.017 ms  (x5.431)  virtual        unique_ptr ランダム順
  4.373 ms  (x3.947)  virtual        Shape* 型ごとにソート
```

最適化レベル別 (ケース1 の CRTP / virtual連続配置 / virtual unique_ptr)

| オプション | CRTP | virtual (連続) | virtual (unique_ptr) |
|---|---|---|---|
| `-O0` | 11.96 ms | 11.46 ms | 25.25 ms |
| `-O2` | 0.95 ms | 2.51 ms | 2.79 ms |
| `-O3` | 1.01 ms | 2.46 ms | 2.99 ms |
| `-O3 -march=native` | 0.97 ms | 2.31 ms | 2.73 ms |

## 分かったこと

### 1. `-O0` では差がない
最適化なしだと CRTP の `area()` → `area_impl()` も普通の関数呼び出しになるので、virtual と変わらない。
**CRTP が速いのは「インライン展開できるから」** であって、仮想関数テーブルを引かないこと自体の効果は小さい。

### 2. `-O2` 以上では CRTP が約2.5倍速い
`-O2` のアセンブリを見ると違いがはっきりする。

CRTP: ループの中に関数呼び出しがなく、`r * r * π` が直接埋め込まれている

```asm
.L254:
	movsd	(%rax), %xmm1
	addq	$8, %rax
	movapd	%xmm1, %xmm0
	mulsd	%xmm3, %xmm0
	mulsd	%xmm1, %xmm0
	addsd	%xmm0, %xmm2
	cmpq	%rax, %rdx
	jne	.L254
```

virtual: 毎回 vptr を読んで間接呼び出し (`call *16(%rax)`)。呼び出しをまたぐので合計値をスタックに退避・復帰している

```asm
.L203:
	movq	(%rbx), %rdi
	movsd	%xmm1, 8(%rsp)
	addq	$8, %rbx
	movq	(%rdi), %rax
	call	*16(%rax)
	movsd	8(%rsp), %xmm1
	addsd	%xmm0, %xmm1
	cmpq	%rbx, %rbp
	jne	.L203
```

また、vptr があるぶん `VCircle` は 16 バイト、`CCircle` は 8 バイトなので、CRTP の方がメモリ帯域も半分で済む。

### 3. 型が混在すると virtual はさらに遅くなる
ランダム順に並んだ Circle / Rect を virtual で呼ぶと、呼び先が毎回変わって **間接分岐の予測が外れる** ため約5.4倍遅くなる。
同じオブジェクトを型ごとにソートしただけで 6.0ms → 4.4ms に改善するので、分岐予測ミスの影響が大きいことが分かる。

ただし CRTP は `ShapeBase<CCircle>` と `ShapeBase<CRect>` が別の型なので、そもそも1つのコンテナに混ぜて入れられない。
ここでは型ごとに別の vector に分けて比較している (公平な比較というより「CRTP で書くとこういう構造になる」という比較)。

### まとめ
- 差の正体は **インライン展開 / 間接分岐の予測ミス / vptr によるオブジェクトサイズ増**
- 1回の呼び出しの中身が軽い (今回のような数回の乗算) ほど差が目立つ。中身が重い処理なら呼び出しコストは誤差になる
- 実行時に型を混ぜて扱いたいなら virtual (か `std::variant`) が必要で、CRTP はコンパイル時に型が決まる場面向け
