制約はクラスの境界(インタフェース)におき，内部の自由度は残す考え．
```C++
class WillItMove
{
public:
    WillItMove() = default;
    WillItMove(WillItMove&&) = default;
    WillItMove(const WillItMove&) = default;
    WillItMove& operator=(WillItMove&&) = default;
    WillItMove& operator=(const WillItMove&) = default;

    const Member& member() const & { return member_; }//ここがポイント
    Member member() && { return std::move(member_); }

private:
    Member member_{};
};
```

理由
- ムーブコンストラクタ/代入が正しく生成され、実際にムーブされる
- 標準コンテナ・アルゴリズムで普通に使える
- 利用者から見た不変性は変わらない
- 将来「実は遅延初期化したい」「キャッシュを持ちたい」となっても、外部インタフェースを壊さずに実装を変えられる
