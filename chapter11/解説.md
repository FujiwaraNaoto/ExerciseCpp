```sh
$ ./p

Bound reference 2
Free memory area 3

```

延長されるのはあくまでもreference3が直接バインドされている`DataSource`の一時オブジェクトのみ．



# 関連する問題を実行した結果

```sh
$ g++ range-for.cpp -o p -std=c++17
$ ./p
Memory area number: -47757202
Memory area number: 5
Memory area number: -142253172
```

ゴミデータが入った結果となっている．最悪の場合はクラッシュする．



範囲for文は以下のようになる
```C++
{
    auto&& __range = MemoryAreaContainer().getMemoryAreas();  // ← range-init
    auto __begin = __range.begin();
    auto __end   = __range.end();
    for (; __begin != __end; ++__begin) {
        const auto& area = *__begin;
        // ループ本体
    }
}
```

`__range`がバインドしているのは`MemoryAreaContainer().getMemoryAreas()`の結果である。参照が直接バインドした相手が一時オブジェクトなら延命するが，今回バインドするのは`MemoryAreaContainer()`オブジェクトのメンバである`memoryAreas_`。
したがって延命は発動しない。 


以下なら延命される (`memoryAreas_`がpublic前提になりますが)
```C++
auto&& r = MemoryAreaContainer().memoryAreas_; // 直接メンバを見ている
```

以下の場合も延命される
```C++
const auto& c = MemoryAreaContainer(); // MemoryAreaContainerオブジェクト自体を見ている
```

# メモ

非constの左辺値参照はprvalueにバインドできない，理由は右辺値は消えることが確定しているため値の置き換えが意味を持たないため言語レベルで禁止されている。
