# x86-64で解析

[godbolt](https://godbolt.org/)で試した結果 (x86-64 gcc11.4)

```
getResource():
        push    rbp
        mov     rbp, rsp
        mov     QWORD PTR [rbp-8], rdi ; 第一引数の値
        nop
        mov     rax, QWORD PTR [rbp-8]
        pop     rbp
        ret

main:
        push    rbp
        mov     rbp, rsp
        sub     rsp, 16 ; 16byteの領域を確保．resource1,r2の内容を確保
        lea     rax, [rbp-1] ;resource1用の領域アドレス. Resouceには何も要素がないので1byteのみ確保．ここでのraxは単純に値を媒介するためのもの。
        mov     rdi, rax     ; 隠し第一引数
        call    getResource()
        lea     rdx, [rbp-1] ; &resource1
        lea     rax, [rbp-2] ; &r2
        mov     rsi, rdx ; 第二引数
        mov     rdi, rax ; 第一引数 this
        call    Resource::Resource(Resource const&) [complete object constructor]
        mov     eax, 0
        leave
        ret
```

<details>
<summary> アセンブリの読み方 </summary>

- `[]`はメモリオペランドであり，そのアドレスにある中身を表す記号(Cでいうとポインタの中身にアクセスする`*`に該当する)

- lea=(Load Effective Address) 指定したメモリアドレスの計算結果(実行アドレス)をレジスタに格納する命令．lea命令の場合は`[]`の中の計算だけをしてメモリアクセスは行わない。



例
- `mov x, y`: yの値をxにコピーする
- `mov x, [y]` : アドレスyに格納されているデータ(デリファレンス結果)をxにコピーする
- `lea x, [y]` : yそのものの数値をxに代入する．

x86-64アーキテクチャでは
- 関数の第一引数はrdiに格納される．
- 関数の第二引数はrsi,
- 返り値はraxレジスタに代入される．(今回の話では特に使われない)


つまりアセンブリレベルでは以下のように書き換えられている．
配置newを用いていることに注意。

```C++
// 戻り値の置き場所を呼び出し側が用意し、そのアドレスを隠し引数で渡す
void getResource(Resource* r)   // r は rdi
{
    ::new (r) Resource{};       // placement new = r の指す場所に直接構築
}

int main()
{
    alignas(Resource) char buf1[sizeof(Resource)];  // rbp-1
    alignas(Resource) char buf2[sizeof(Resource)];  // rbp-2

    getResource(reinterpret_cast<Resource*>(buf1)); // = resource1
    ::new (buf2) Resource{*reinterpret_cast<Resource*>(buf1)}; // = r2
}
```



# 他のバージョンと最適化レベルを変えて行う

最適化レベルを最低にして言語バージョンを変えても結果は同じ。
`-O0`はあくまでも最適化を弱めるフラグであり言語使用であるコピー省略は最適化とは別枠。

```sh
$ g++ counting-copies.cpp -o p -std=c++23 -O0
$ ./p
copy
$ g++ counting-copies.cpp -o p -std=c++17 -O0
$ ./p
copy
```




`-fno-elide-constructors`(コンパイラが本来省略していた中間オブジェクトをそのまま作られるオプション)をつけると3回のコピーになることがわかる．
```sh
$ g++ counting-copies.cpp -o p -std=c++17 -O0 -fno-elide-constructors
$ ./p
copy
$ g++ counting-copies.cpp -o p -std=c++11 -O0 -fno-elide-constructors
$ ./p
copy
copy
copy
```

3回のうち
- 1回目は`getResource()`による一時オブジェクト
- 2回目は`resource1 = getResource()`による戻りオブジェクト
- 3回目は`r2{resource1};`の部分

コピーコンストラクタをユーザ定義することでムーブコンストラクタが暗黙生成されないことに注意



C++14までは一時オブジェクトを作ってからコピー・ムーブし，それをコンパイラが省略しても良いだった。そのため，コピーが1と2回目で走っている。C++17ではprvalueは初期化される対象が決まるまでオブジェクトを実体化しない(遅延実体化)として定義され直した。
