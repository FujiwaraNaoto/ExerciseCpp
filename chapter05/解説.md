# 発展課題

以下のようにコードを変更する．

```diff
struct Widget{
    virtual void draw(){std::cout<<"Widget draw()"<<std::endl;}
-   virtual ~Widget(){std::cout<<"Widget destructor"<<std::endl;}
+   ~Widget(){std::cout<<"Widget destructor"<<std::endl;}
};
```

実行結果 (未定義動作)
```sh
$  g++ a-destructive-relation.cpp -o p
$ ./p
Button draw()
Widget destructor
```
実際にはリソースが解放されないことが起こるので基底クラスのデストラクタは`virtual`をつけるのがマナー


# rule of 5 違反

Buttonクラスの場合:`~Button()`を書くべきではない
理由: ユーザ定義のデストラクタを宣言することでムーブコンストラクタとムーブ代入は暗黙宣言されなくなる．

参考　https://accu.org/conf-docs/PDFs_2014/Howard_Hinnant_Accu_2014.pdf


C:20 [If you can avoid defining default operations, do](
https://github.com/isocpp/CppCoreGuidelines/blob/master/CppCoreGuidelines.md#c20-if-you-can-avoid-defining-default-operations-do)


C:21 
[If you define or =delete any copy, move, or destructor function, define or =delete them all](https://github.com/isocpp/CppCoreGuidelines/blob/master/CppCoreGuidelines.md#c21-if-you-define-or-delete-any-copy-move-or-destructor-function-define-or-delete-them-all)


Widigeクラスの場合: 多相基底クラスなのでコピーとムーブを封じる
理由: スライシングの防止


C:67  [A polymorphic class should suppress public copy/move](https://github.com/isocpp/CppCoreGuidelines/blob/master/CppCoreGuidelines.md#c67-a-polymorphic-class-should-suppress-public-copymove)

集成体の定義のバージョン推移
| 条件 | C++98 / 03 | C++11 / 14 / 17 | C++20 / 23 / 26 |
|---|---|---|---|
| コンストラクタ | user-**declared** コンストラクタを持たない | user-**provided** / `explicit` / 継承 コンストラクタを持たない<br>(`explicit`・継承の制限は CWG 1518 により C++11 へ遡及適用) | user-**declared** / 継承 コンストラクタを持たない |
| 非静的データメンバ | private / protected な直接非静的データメンバを持たない | 同左 | 同左 |
| 基底クラス | 基底クラスを持たない | **C++11/14**: 基底クラスを持たない<br>**C++17**: 仮想基底クラスを持たず、private / protected な直接基底クラスを持たない<br>(private/protected な間接基底は可 — CWG 2610 が C++17 へ遡及適用) | 仮想基底クラスを持たず、private / protected な直接基底クラスを持たない |
| 仮想メンバ関数 | 持たない | 持たない | 持たない |
| NSDMI(`int x = 0;`) | 機能自体が存在しない | **C++11**: 持てない(持つと非集成体)<br>**C++14 以降**: 持てる | 持てる |

※ 配列型はどのバージョンでも常に集成体。
※ 「user-provided」= 自分で宣言し、かつ最初の宣言で `= default` / `= delete` していない関数。
- user-declared : クラス内で自分で宣言した
- user-provided: 自分で宣言し，かつ最初の宣言で`=default`/`=delete`してない．


コピーコンストラクタをuser-declareした時点で集成体ではなくなり，コンストラクタを1つでも宣言すると暗黙のデフォルトコンストラクタは生成されないため `X{}`を書けなくなる．

`=default`をクラス外に書くとuser-providedとなり，C++11時点ですでに集成体ではなくなる．

```C++
struct Y { int a; Y(const Y&); };
Y::Y(const Y&) = default;   // user-provided → C++11 以降どのバージョンでも非集成体
```

`=default`/`=delete`したコピー/ムーブコンストラクタはC++17までは集成体のまま，C++20では非集成体になる．(C++11~C++17の条件がuser-providedベース，C++20がuser-declaredベースであるため)
